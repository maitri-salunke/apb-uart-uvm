# apb-uart-uvm

UVM verification of an AMBA 3 APB UART, written in SystemVerilog and run on
open-source tools only: **Verilator 5.054 (`--timing`) running the Accellera
UVM library** (IEEE 1800.2-2020 kit 2020.3.2, the
[chipsalliance/uvm-verilator](https://github.com/chipsalliance/uvm-verilator)
distribution). It uses real UVM throughout (factory, phases, config_db, TLM,
RAL), with no Python framework standing in for it.

Author: Maitri Salunke

## What is in it

| Part | Where |
|---|---|
| RTL: APB slave (PREADY wait state, PSLVERR), 16-deep TX/RX FIFOs, baud generator (16x), TX, RX with 2-flop synchronizer + majority vote, parity, loopback, sticky W1C interrupts | `rtl/` (lint clean with `verilator --lint-only -Wall`) |
| Register map | [docs/REGISTERS.md](docs/REGISTERS.md) |
| Verification plan (28 items) | [docs/VPLAN.md](docs/VPLAN.md) |
| UVM env: APB agent, UART agent (serial driver with error/skew injection, two monitors), RAL model + adapter + explicit predictor, reference-model scoreboard, 10 covergroups, virtual sequencer, 10 virtual sequences, 10 tests | `tb/` |
| SVA: 21 assertions (14 APB protocol, 7 DUT white-box) + 5 cover properties | `tb/sva/` |
| Regression, coverage merge, mutation campaign | `scripts/`, `Makefile` |
| Design notes for every component | [docs/DESIGN.md](docs/DESIGN.md) |
| Bugs the environment found in the RTL | [docs/BUGS.md](docs/BUGS.md) |

                 |                   |         |                   tx_mon <-+|  |   |
                 |   predictor <-----+         |                            ||  |   |

## Running it

Requirements (macOS/Homebrew; Linux works the same):
`brew install verilator ccache z3` (Verilator 5.054; z3 is the constraint
solver Verilator calls for `randomize()` with constraints), Python 3.

```sh
scripts/get_uvm.sh            # fetches the pinned UVM kit into third_party/ (make does this too)
python3 -m venv .venv          # scripts use only the standard library
make lint                      # RTL lint
make build                     # ~4-7 min first time (UVM is large), ccache helps later
make test TEST=uart_rx_test SEED=7
make regress N=500             # seeds 1..N round-robin over the 10 tests, <=4 parallel
make cov                       # merge coverage of the last regression -> logs/regress/coverage/
make mutate                    # 14 RTL mutants x (10 tests x 2 seeds)
```

On macOS the UVM DPI code needs a `<malloc.h>` shim (`tb/compat/malloc.h`) and
`--vpi` for `uvm_hdl_*`; both are already in the Makefile.

## Results

All numbers below come from the commands shown, run on an Apple Silicon Mac
(Verilator 5.054, 4 parallel jobs). Logs are regenerated by the commands; they
are not committed.

| Metric | Result | How it was measured |
|---|---|---|
| Framework | Real SystemVerilog UVM (Accellera 1800.2-2020 kit 2020.3.2) on Verilator 5.054 `--timing` | `make build`; every component is a `uvm_*` class |
| Verification plan | 28 items (VP-01 .. VP-28) | [docs/VPLAN.md](docs/VPLAN.md) |
| Regression | **500 / 500 seeds pass** (10 tests x 50 seeds, seeds 1-500), 110 s wall | `make regress N=500` |
| Second configuration | 100 / 100 seeds pass with `WAIT_STATES = 0` (seeds 1001-1100) | `make regress-ws0 N=100` |
| Scoreboard checks | 11,069,622 compares across the 500 runs, 0 mismatches; 23,934 comparisons (0.2 %) skipped by the settling window and counted | sum of `[SB] checks=` / `skipped_unsettled=` in the logs |
| Functional coverage | **100 %**: 10 covergroups, 217 bins, 0 holes (merged) | `make cov` (Verilator covergroup bins from `coverage.dat`) |
| Line (block/branch) coverage, rtl/ | 98.39 % raw (122/124); 100 % after 2 waivers (unreachable FSM `default` arms) | `make cov` |
| Toggle coverage, rtl/ | 94.07 % raw (967/1028); 100 % after 61 waived points (reserved PRDATA bits, tied reg_addr[1:0], reset 1->0, baud counter bits 12-15) | `make cov`, waivers in `scripts/cov_waivers.txt` |
| Assertions | 21 concurrent SVA (14 APB protocol: setup->access, stable PADDR/PWRITE/PWDATA, PREADY timeout, no X on PSEL, ...; 7 DUT white-box) + 5 cover properties; 0 failures in regression | `tb/sva/` |
| Mutation campaign | **14 / 14** injected RTL bugs caught (each: 10 tests x 2 seeds) | `make mutate`, [docs/MUTATIONS.md](docs/MUTATIONS.md) |
| Real RTL bugs found | **0** (6 testbench bugs found and fixed during bring-up) | [docs/BUGS.md](docs/BUGS.md) |
| RTL lint | clean under `verilator --lint-only -Wall` | `make lint` |

Coverage closure: after the first 45-seed regression, functional coverage was
94.9 % with 12 holes (DIV = 0, RX_THR = 0/16, a W1C "keep" case, TX data
0x00). The cause was a `dist` weighting mistake (`:=` vs `:/`) and a loop
order, not missing features (BUGS.md T4, T6). After those fixes, 300 seeds
reached 100 % and the 500-seed run above confirms it. The bins are fairly
coarse (217 in total), so 100 % here means every planned scenario happened
at least once. It does not mean every combination did.

## Limitations (honest list)
- One simulator only (Verilator). Coverage numbers come from Verilator's
  covergroup and line/toggle implementation, not from Questa/VCS.
- No reset in the middle of traffic; divisors above 2100 are not run (see
  the waivers and "out of scope" in the plan).
- The DUT is my own design, so "bugs found" are bugs in my RTL, listed in
  docs/BUGS.md with how they were found.
